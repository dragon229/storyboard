# 語音稿 → 分鏡稿提示詞 轉換規範（階段二）

本檔是四階段流程的**階段二**規範：把一個場景（來自階段一的場景清單）轉成完整的 **`prompt`（直接送進 ComfyUI 的最終提示詞）** 與 **`claims`（Stage 4 驗證用清單）**。

> **架構說明**：Stage 2 LLM 一步完成所有工作——場景描述、世界觀、環境、供電、角色造型、喪屍分型等全部由 LLM 根據上下文判斷需不需要加、怎麼加。不再有 Stage 3 compose 步驟。`分鏡稿規範.json` 是 Stage 2 的**參考資料**（角色外觀、環境描述文字、供電閾值等），而非腳本執行的設定檔。

---

## 核心原則：一個畫面只聚焦「一件最重要的事」

每個分鏡只表達該段文字裡**最重要的單一焦點**，畫面盡量單純。其餘次要的人物、動作、道具**一律不寫進 prompt**。

> 例：Day 3 餐廳，阿偉端餐盤看電視新聞。
> 最重要的是「電視在播什麼」→ 焦點＝**一個大大的電視螢幕，播放市立醫院封鎖的新聞**。
> 阿偉、餐盤、餐廳細節都**不寫**。

---

## 轉換步驟

1. **讀整段語音稿**，找出這一格分鏡最該讓觀眾看到的**單一焦點**。
2. **判斷焦點類型**（見下），決定鏡頭遠近。
3. **讀 `分鏡稿規範.json`**，取得需要的參考資料：風格前綴（`common.style`）、角色造型、喪屍分型、供電閾值。
4. **組合完整 `prompt`**（見「完整 Prompt 組合規則」）。
5. **生成 `claims` 清單**（見「Claims 生成規則」）。
6. 填入場景資料：
   - `scene`（中文）：簡短描述，**若焦點是某角色，要含該角色中文名**。
   - `dialogue`（中文）：對應台詞，僅作紀錄。
   - `prompt`：完整最終提示詞。**這是階段二的產物**，直接送進 ComfyUI。
   - `claims`：Stage 4 驗證用的逐條清單。
7. **跑驗證清單**（A1–C6），任一不過就改寫，最多 5 次；第 5 次仍失敗標記人工確認。

---

## 完整 Prompt 組合規則

Prompt 是以下 block 的有序組合。**每個 block 都有加入條件**，不是每格都要全部加。

### 必有格式

```
[style] — [場景描述], [加入的 block...], [情緒語句]
```

- `[style]`：從 `分鏡稿規範.json` 的 `common.style` 取值，每格都一樣。
- `—`：固定分隔符，style 與場景描述之間。
- `[場景描述]`：本格的焦點描述（構圖、姿態、地點等）。
- `[情緒語句]`：必有，寫在最後。

---

### Block 1：世界觀（`common.prompt`）

**來源**：`分鏡稿規範.json` → `common.prompt`

**加入條件**：
- ✅ 環境焦點、全景、遠景場景 → 加
- ✅ 人物焦點且可見背景空間（MCU 以上景別）→ 加
- ❌ 物件 ECU / 極特寫（畫框裡只有物件，看不到任何背景）→ **跳過**
- ❌ 人物 ECU / 臉部極特寫（背景虛化到消失）→ **跳過**
- ❌ 軍事基地室內、電廠廠房等封閉機構場景 → **跳過**「city recently abandoned」類城市描述，改用符合場景的描述（例：`a tense and orderly military environment`）

---

### Block 2：環境描述（`environments`）

**來源**：`分鏡稿規範.json` → `environments` 陣列，按 `name` 選擇。

**選環境名稱**：

| 地點類型 | 環境名稱 |
|---------|---------|
| 電廠（渦輪廳/控制室/廠房）| `power_plant` |
| 工業室內（加壓站/一般控制室）| `industrial_interior` |
| 醫療區 | `medical` |
| 郊野/公路 | `rural` |
| 城市室外 | `outdoor_city` |
| 其他室內（走廊/辦公室/宿舍）| `interior_generic` |

**版本選擇**：
- `prompt_wide`：人物焦點（MCU/MS/FS）、動作焦點、環境焦點、關係焦點、對比焦點 → 使用
- `prompt_close`：物件焦點、細節提示焦點、ECU → 使用
- **完全跳過**：場景描述本身已完整描述環境、加了會重複時

---

### Block 3：供電光線

**來源**：`分鏡稿規範.json` → `power` 物件

**天數判斷**：從 `scene` 欄位擷取爆發後天數：
- `Day NN` → N 天
- `北上第X天` / `北行第X天` → 約第 60 天
- `Day ?` / 終章 → 第 73 天

**選擇**：

| 天數範圍 | 室內選 | 室外選 |
|---------|-------|-------|
| Day ≤ 14 | `power_intact_indoor` | `power_intact_outdoor` |
| Day 15–39 | 工業/醫療用 `power_partial_industrial`；其他室內用 `power_partial_indoor` | `power_partial_outdoor` |
| Day 40–41 | `failing_night` | `failing_night` |
| Day ≥ 42 | `blackout_indoor` | `blackout_outdoor` |

**跳過條件**：
- ❌ 物件 ECU（筆記本頁面填滿畫框，看不到任何光源）→ **跳過**
- ❌ 戶外自然光場景（白天、雨、霧）→ 改用天氣描述，不加供電文字

---

### Block 4：世界觀（人物污垢）

**來源**：`分鏡稿規範.json` → `world_characters.prompt`

**加入條件**：
- ✅ 有人物出現，且人物臉部/衣物在畫框中可見 → 加
- ❌ `no_characters: true` 的場景 → **跳過**
- ❌ 人物 ECU 但臉部未在畫框中（例：只拍到手）→ **跳過**

---

### Block 5：角色標記（inline 標記法）

**來源**：`分鏡稿規範.json` → `characters` 陣列（僅供判斷哪些角色有參考圖）

**核心改變**：角色外觀**不再**用一段獨立文字在句尾統一注入，改成在場景描述裡角色出現的位置**就地標記**。原因：當使用角色參考圖工作流（`image_anima_base_v1_char` / `image_anima_base_v1_char_scene`）時，外觀已由參考圖提供，句尾再寫一次文字外觀會造成冗餘、與參考圖衝突、且多人場景中模型無法辨識參考圖該貼到哪個人。

**判斷「有無參考圖」**：某具名角色算不算 `(reference image)`，依據要和 generate.py 的 `detect_primary_character_ref` 一致 —— 該角色須在 `CHARACTER_ROLE_MAP` 有對應、且 `roles/` 資料夾實際有那張 `XXX.png`。目前有參考圖的角色：**林志遠、老張、阿偉、小陳、盧醫官、老李、陳雅芳**。

**標記規則**：

| 情況 | 寫法 | 外觀細節 |
|------|------|---------|
| **有參考圖的主角** | 最小身分識別 ＋ `(reference image)`，例：`an older stocky soldier (reference image)` | **丟掉**髮型、鬍渣、軍階等細節，只留職業/性別/體型當定位錨點 |
| **其他角色**（無參考圖的具名角色、背景人物） | 簡單身分 ＋ `(other character)`，例：`a senior officer (other character)` | 只留職業/性別，避免模型把參考圖的臉複製過去 |
| **無參考圖工作流**（`image_anima_base_v1`） | 不加 `(reference image)` 標籤（沒圖可貼），角色仍給簡單職業/性別描述 | 只留簡單描述（至少職業或性別） |

**重要限制**：一格畫面**只能有一個 `(reference image)`**（`_char` 工作流只吃一張 `input_character.png`），其餘所有人一律 `(other character)`。多個具名主角同框時，選焦點角色當 reference，其餘標 other。

**加入條件**：
- ✅ 某角色是焦點或在畫框中可辨識 → 就地標記（有參考圖標 `(reference image)`，否則簡單描述）
- ✅ 有「士兵、下士、哨兵」等一般軍人稱謂 → 標 `(other character)`（一般軍人無專屬參考圖）
- ❌ `no_characters: true` 的場景 → **跳過所有角色**
- ❌ 構圖只露出局部身體（ECU 手部）→ **跳過**（加了反而矛盾）

> 場景描述只寫**姿態、動作、位置**，加上**最小身分識別＋標記**；不要寫髮型/鬍渣/軍階等細節外觀（有參考圖時由圖提供，無參考圖時保持簡單即可）。

**必填欄位 `ref_character`（Option B — 唯一真相來源）**：每格 JSON 必須輸出 `ref_character` 欄位，記錄「這格要載入誰的參考圖」，讓 generate.py **直接讀欄位、不再自己用關鍵字猜**（避免第一人稱主角漏偵測、感染者被誤貼臉等不同步）。

- 值 = 標成 `(reference image)` 的那位角色中文名（如 `"老張"`、`"林志遠"`）。
- 值 = `null` → 這格不載任何參考圖（`no_characters`、感染者、無臉 ECU、或畫面中角色皆無專屬參考圖時）。
- **必須與 prompt 一致**：`ref_character` 非 null ⇔ prompt 內有且僅有一個 `(reference image)`；`ref_character` 為 null ⇔ prompt 無 `(reference image)`。
- 一格只能有一個 `ref_character`（呼應「一格只有一個 `(reference image)`」）。
- 特例：**感染/轉化的角色**即使場景提到其名字，也要標 `null`＋prompt 用 `(other character)`（劇情上「那已不是他的臉」，不可貼原參考臉）。例：s55/s56 感染的盧醫官。

> generate.py 的 `detect_primary_character_ref` 已改為優先讀此欄位；欄位不存在時才退回舊的關鍵字比對（相容未標註的舊系列）。

---

### Block 6：喪屍分型

**來源**：`分鏡稿規範.json` → `zombie_types`

**加入條件**：場景中確實有感染者出現時才加。根據環境名稱選分型：
- `power_plant` / `industrial_interior` → `industrial_clause`
- `medical` → `medical_clause`
- 軍事基地 → `soldier_clause`
- 其他 → `default_clause`

---

### Block 7：戰鬥破壞素材

**來源**：`分鏡稿規範.json` → `combat.destruction_outdoor` 或 `destruction_indoor`

**加入條件**：
- 場景含戰鬥/清掃關鍵字（清掃、路障、壓制、射擊、感染者…）
- 且不含安全排除字（簡報、餐廳、辦公室、點名、命令紙…）
- 郊野/純鄉道場景 → **不加**
- 加的話：室外從 `destruction_outdoor` 隨機選 1–2 項；室內從 `destruction_indoor` 選

---

### Claims 生成規則

每加入一個 block，就在 `claims` 清單裡加一條。**只加實際加進 prompt 的 block**，跳過的 block 不寫進 claims。

```json
{"label": "場景描述", "text": "<場景描述的完整英文>"}
{"label": "世界觀",   "text": "<加入的 common.prompt 文字>"}
{"label": "環境",    "text": "<加入的 environment prompt 文字>"}
{"label": "供電光線", "text": "<加入的 power clause 文字>"}
{"label": "世界觀(人物)", "text": "<加入的 world_characters prompt 文字>"}
{"label": "角色標記", "text": "<場景描述中的角色定位＋標記，例：an older stocky soldier (reference image); a senior officer (other character)>"}
{"label": "喪屍分型", "text": "<加入的 zombie type 文字>"}
```

> **角色 claim 改法**：不再輸出「角色外觀」的細節文字 claim（髮型、軍階等）。改輸出「角色標記」claim，記錄場景裡每個角色的**定位＋標記**（`(reference image)` / `(other character)`）。Stage 4 驗證時檢查：reference 角色是否與參考圖一致、other 角色是否為不同的人（未複製參考臉）。

## 畫面設計規範：焦點類型 × 景別 × 視角 × 構圖

每張分鏡的畫面由四個維度共同決定最終感受：**焦點類型**（拍什麼）× **景別**（拍多遠）× **視角**（從哪個角度）× **構圖**（怎麼排列元素）。

> **靜態圖限制**：本專案生成單張靜態圖，無法呈現鏡頭運動過程（Rack Focus、推軌等），只能呈現一個瞬間的狀態。前景/背景虛化等屬於靜態可呈現的構圖技巧，可附加於下列任何類型。

---

### 速查：四個維度

**景別（Shot Scale）**

| 縮寫 | 中文 | 涵蓋範圍 | 用途 |
|------|------|---------|------|
| ECU | 極特寫 | 局部器官或物件細部 | 線索放大、細節強調、極度張力 |
| CU | 特寫 | 臉部或物件主體，少量環境 | 情緒讀取、重要物件展示 |
| MCU | 中近景 | 胸部以上，含表情與部分肢體 | 情緒與肢體語言並呈 |
| MS | 中景 | 腰部以上，含少量空間 | 動作與人物關係的平衡點 |
| FS/LS | 全景/遠景 | 全身＋周遭空間 | 動作全貌、人與環境的尺度對比 |
| ELS | 超遠景 | 廣大場景，人物極小 | 規模感、孤立感、世界觀建立 |

**視角（Camera Angle）**

| 類型 | 感受 |
|------|------|
| 水平視角（Eye-level） | 共情、平等、觀察者立場，最接近日常感知 |
| 俯角（High angle） | 壓迫感、角色顯得渺小或脆弱 |
| 仰角（Low angle） | 威脅感、力量、緊張；或角色顯得高大堅定 |
| 鳥瞰（Bird's eye / Top-down） | 客觀全局、疏離感；適合展示陣型或空間分布 |
| 斜角（Dutch angle） | 心理不穩定、扭曲、恐懼或錯亂感 |

**構圖（Composition）**

| 手法 | 效果 |
|------|------|
| 三分法 | 視覺自然平衡，主體置於交叉點，留出視線或動作空間 |
| 黃金分割 | 三分法的精緻版，主體置於黃金比例交叉點，比三分法略更「自然正確」的感覺 |
| 中心對稱 | 強調主體的重量感、莊嚴、孤立或威脅 |
| 透視引導線 | 帶出空間深度，視線被引向消失點 |
| 框中框（門窗/洞口） | 限制感、被監視、孤立在另一個世界 |
| 對角線 | 動感、不穩定、衝突或緊張 |
| 留白（Negative Space） | 孤獨、渺小、情緒的呼吸空間 |
| 剪影（Silhouette） | 輪廓優先，身份模糊，象徵性強 |
| 過肩（Over-the-Shoulder） | 主觀視角、關係對立、代入感 |
| 雙人景（Two-Shot） | 人物關係展示、對話張力、對比 |
| L 型構圖 | 穩定中帶有不對稱，適合多人三角關係 |

---

### 七大焦點類型 × 取景組合

#### 1. 物件焦點
**敘事目的**：著重物品的特徵、質感或對劇情的重要性；物件本身是這一格的信息載體。

| 組合名稱 | 景別 | 視角 | 構圖 | 感受 | 適用情境 |
|---------|------|------|------|------|---------|
| **置中特寫** | CU / ECU | 水平 | 中心對稱 | 莊重、明確、物件感覺很重要 | 命令紙、資料夾、徽章等「有份量的東西」 |
| **黃金分割特寫** | CU | 水平偏俯 | 黃金分割交叉點 | 自然、真實、略帶觀察感 | 筆記本、水杯等日常物件 |
| **裁切神秘** | ECU | 正面/微俯 | 裁切構圖（物件局部出框） | 未知感、物件不完整、吸引觀眾想像全貌 | 僅露出局部的線索型物件（半張紙、被遮住的名單） |
| **俯拍鋪陳** | CU | 鳥瞰 | 物件置中或對角線 | 客觀、物件被「陳列」出來、略帶冷靜疏離 | 地圖上的標記、桌上的多件物品排列 |

> 物件焦點必須加 `no people visible`，並設 `no_characters: true`。物理狀態（放在桌上/牆上/地上）必須寫清楚。

---

#### 2. 人物焦點
**敘事目的**：著重角色的情緒、心理狀態或台詞表達；觀眾需要「讀臉」或感受角色的重量。

| 組合名稱 | 景別 | 視角 | 構圖 | 感受 | 適用情境 |
|---------|------|------|------|------|---------|
| **平視中近景** | MCU | 水平 | 三分法（視線側留空間） | 共情、平等、觀察者感 | 大多數情緒場景的首選，拉近但不壓迫 |
| **平視特寫** | CU | 水平 | 中心或三分法 | 情緒高張、強制讀臉 | 決定性瞬間、情緒爆發、無法迴避的眼神 |
| **低仰角中近景** | MCU | 低仰 | 不對稱 | 角色顯得堅定或壓迫，觀眾感到下方 | 林少校下令、王中校宣布任務等權威時刻 |
| **俯角中景** | MS | 高俯 | 三分法或中心 | 角色顯得渺小脆弱、被環境壓住 | 獨自面對困境、絕望時刻 |
| **剪影全景** | FS / LS | 水平或低仰 | 中心留白，主體剪影 | 輪廓與象徵感，身份感模糊但存在感強 | 夕陽/逆光場景、女孩往北走、出發前的身影 |

---

#### 3. 動作焦點
**敘事目的**：強調一個關鍵動作、動態軌跡或爆發的瞬間；靜態圖捕捉動作的「決定性一刻」。

**先問動作的身體參與範圍，再決定景別：**

| 參與範圍 | 景別 | 說明 |
|---------|------|------|
| **全身參與**（格鬥、被壓制、舉槍、奔跑、翻牆） | MS / FS | 需要看到全身動態才能理解動作 |
| **局部身體部位**（一隻手推資料夾、扣扳機、翻頁） | CU / ECU | 只框入該部位＋互動物件；不寫全身姿態（兩者矛盾模型會選中景） |

| 組合名稱 | 景別 | 視角 | 構圖 | 感受 | 適用情境 |
|---------|------|------|------|------|---------|
| **水平對角全身** | MS / FS | 水平 | 對角線構圖，動作方向與對角線一致 | 動感、衝突、不穩定 | 格鬥、衝鋒、被壓制等激烈動作 |
| **低仰全身** | FS | 低仰 | 主體居中或對角 | 動作感覺更強大、更有衝擊力 | 老張反手一刀、少校舉槍朝天 |
| **水平局部特寫** | CU / ECU | 水平微俯 | 畫框填滿，主體四周無多餘空間 | 精確、刻意、重量感 | 手推資料夾、手翻頁、手指扣扳機 |
| **斜角壓制** | MS | 斜角（Dutch） | 不對稱，壓制者居高；⚠ Dutch angle 是強烈手法，同一系列不宜超過 2–3 格，過量使用會失去衝擊力 | 心理扭曲、失控感、恐懼 | 被感染者壓制、周下士在樓梯間（每集最多保留 1–2 格） |

**局部動作的取景規則（重要）**：
- 只寫「手/該部位＋互動物件」，**不要同時寫全身姿態**——兩者矛盾時模型選中景，特寫意圖失效。
- 用畫框填滿語言鎖定：`only the hand, forearm cuff, and folder visible filling the frame, no face or body visible`
- 若局部入鏡到無法辨識是誰：加 `no people visible` 並設 `no_characters: true`

> **範例（王中校推資料夾）**：
> ❌ `seated at a desk, sliding a folder across the desk with one hand, only his hand and forearm emphasized, medium shot`（medium shot 與局部特寫矛盾）
> ✅ `extreme close-up of a desk surface under a desk lamp, a single hand sliding an open folder across the wood toward the viewer, only the hand, forearm cuff, and folder visible filling the frame, no face or body visible`

**動作焦點的空間位置描述**：必須明確說明每個參與者的空間關係，而不是只描述動作結果。寫前回答：
1. 主角在哪裡？（背靠牆？站在樓梯上？蹲在地面？）
2. 對象從哪個方向來？（左側？正面？從上方壓下？）
3. 接觸點是什麼？（手抓肩膀？身體全重壓住？）
4. 關鍵道具的位置？（槍被夾在身體和牆壁之間？）

> **範例（周下士被壓制）**：
> ❌ `a soldier pinned by zombies in a stairwell, rifle trapped, desperate struggle`
> ✅ `a soldier with his back pinned against a stairwell corner wall — one zombie pressing its full body weight from the left, a second grabbing his right shoulder from the front, a third bearing down from the stairs above on his right — his rifle trapped horizontally between his right side and the concrete wall, barrel pointing at the wall, impossible to raise`

#### 4. 環境焦點
**敘事目的**：交代故事背景、世界觀、規模或空間氛圍；人物極小或不出現，場景本身是主角。

| 組合名稱 | 景別 | 視角 | 構圖 | 感受 | 適用情境 |
|---------|------|------|------|------|---------|
| **水平透視遠景** | LS / ELS | 水平 | 單點透視引導線（道路、走廊、橋面） | 深邃、延伸、前方未知 | 霧中空城、車隊駛入、荒廢主幹道 |
| **俯角廣域** | ELS | 高俯 / 鳥瞰 | 留白，主體佔畫面小角落 | 渺小、孤立、環境壓倒人 | 圍牆外密集、廣場上零星身影 |
| **低仰仰望** | LS | 低仰 | 建築/電廠/大橋為主體，天空留白 | 規模感、壓迫、宏大 | 電廠外牆、大橋橋頭、基地入口 |
| **空間明暗分割** | LS / MS | 水平 | 強烈光暗分界線橫切整個空間（Chiaroscuro），明暗各佔畫面一半 | 戲劇張力、危機感、兩個世界的邊界；重點是「整個空間」被切成明暗兩半，而非單一角色 | 燈光/黑暗交界的走廊、基地內外對比、停電後半亮半暗的廠房 |

#### 5. 關係焦點
**敘事目的**：強調兩個或多個主體間的相對位置、階級差異或心理拉鋸；人際空間本身是視覺語言。

| 組合名稱 | 景別 | 視角 | 構圖 | 感受 | 適用情境 |
|---------|------|------|------|------|---------|
| **過肩對峙** | MCU | 水平 | 過肩（OS），前景模糊背景清晰 | 主觀代入、對立感、關係緊繃 | 少校與難民父親隔路障對視、審問或質問場景 |
| **雙人平視** | MS | 水平 | Two-Shot，二人分左右各佔三分位 | 關係展示、對話、平等或對峙 | 何上尉與林少校走廊交談、老張坐到少校旁邊 |
| **前後景尺寸對比** | MS / LS | 水平或微俯 | 前景人物大、後景人物小，縱深拉開 | 階級/權力差異、前景主導後景 | 王中校在地圖前指示、指揮官俯視部隊 |
| **三角對峙（L型）** | MS | 水平 | 三人呈三角或L形排列 | 多方張力、沒有單一焦點的不穩定 | 三人關鍵決策場景、倖存者與軍人交涉 |

#### 6. 對比焦點
**敘事目的**：透過反差本身傳遞訊息——孤立感、內心矛盾、環境的荒謬或殘酷；重點是「兩者之間的落差」。

| 組合名稱 | 景別 | 視角 | 構圖 | 感受 | 適用情境 |
|---------|------|------|------|------|---------|
| **框中框孤立** | MS / FS | 水平 | 門框/窗框作為內框，人物在框內 | 被隔絕、觀察者與被觀察者、另一個世界 | 窗外看基地、隔著玻璃看醫院大廳 |
| **人物半明半暗** | MCU / MS | 水平 | 明暗分界線縱切人物臉部或身體（split lighting），人物一半亮一半暗；與「空間明暗分割」的區別是重點在角色本身而非整個空間 | 內心矛盾、兩面性、承受重壓 | 少校在黑暗中做決定、夜間射擊位守哨 |
| **孤獨留白** | FS / ELS | 水平或俯角 | 人物極小置於畫面一角，大量空白 | 孤立、渺小、被環境遺棄 | 一人獨坐空餐廳、少校站在封死的東側走廊前 |
| **秩序中的荒謬** | MS / LS | 水平 | 「正常元素」置於三分位或中心，清晰銳利對焦，不加遮擋；廢棄的背景自然散落其後形成對比，不需要特別強調背景——兩者的落差靠並置自然產生 | 荒謬感、日常的詭異延續、殘酷而普通的諷刺感 | 空城裡還在變換的紅綠燈（紅綠燈清晰居中，空街道為背景）、陽台上還在飄的衣物（衣物置三分位，廢棄街景虛化其後） |

#### 7. 細節／提示焦點
**敘事目的**：刻意放大場景中的局部，提示關鍵線索或醞釀危機感；單個細節承載敘事密度。

| 組合名稱 | 景別 | 視角 | 構圖 | 感受 | 適用情境 |
|---------|------|------|------|------|---------|
| **極特寫正面** | ECU | 正面水平 | 置中，細節填滿畫框 | 強制注意、無法迴避的線索 | 名單上被劃掉的名字、血跡蔓延的方向 |
| **消失點線索** | CU / ECU | 微俯或水平 | 物件置於透視線終點（引導視線聚焦） | 被引導、線索感覺是「被發現的」 | 走廊末端的一扇門、牆上的日期刻痕 |
| **聚光強調** | ECU | 水平 | 強烈局部光，其餘暗 | 戲劇性、秘密感、孤立線索 | 檔案夾裡被塗掉的文字、繃帶下的傷口 |
| **環境中的細節** | CU | 俯角或微俯 | 細節在較大背景中，但視線被引導到它 | 線索「藏」在環境裡、等待被發現 | 地板積水中的倒影、散落物中的特定物件 |

## 數量的視覺轉換

台詞裡出現「很多、擠滿、密密麻麻、從四面八方」等描述**大規模數量**的字眼時，**不要直接把大量物件塞入畫面**。畫面越密，個體越模糊，規模感反而下降。

正確做法：
1. **選 3–5 個代表性個體**，賦予每個個體明確的質感或差異特徵（不同單位標記、不同損傷、不同方向停放）。
2. **用情緒語句傳達規模**：個體的視覺細節讓觀眾看清楚「一個」，情緒語句讓觀眾感受到「背後還有更多」。
3. **差異性暗示多樣性**：`each from a different unit` 比畫 20 台同款車更能傳達「四面八方調來」的感受。

> 範例：台詞「停車場塞滿各單位的車」→ 不畫滿車場，改畫「三台不同單位的大型軍卡並排，各有不同的車門標記」，情緒語句寫「mass convergence」。

## 場景地點推斷規則

**當某個場景沒有明確指出地點時，必須從前後文推斷並寫進 prompt。** 若省略地點，生圖模型會自行填補，常見錯誤是把室內場景畫成戶外、把軍事場所畫成民居。

### 推斷方式

1. **向前查找**：找最近一個有明確地點的場景，確認人物還在同一個地方。
2. **向後確認**：看這個場景之後有沒有「人物離開／移動」的敘述，有的話才切換地點。
3. **沿用直到有明確切換**：只要沒有描述人物移動，就假設還在同一個地點。

### 地點寫進 prompt 的方式

地點不是焦點，只需用**一個背景描述子句**帶出，不要搶過主焦點。

| 推斷地點 | 寫法範例 |
|---------|---------|
| 軍事連部室內 | `in a sparse military office interior` |
| 軍事基地走廊 | `in a military base corridor` |
| 軍事簡報室 | `in a military briefing room` |
| 軍事餐廳 | `in a military mess hall` |
| 基地戶外停車場（夜） | `in a military base parking lot at night` |
| 廢棄市區街道 | `on an abandoned city street` |
| 公寓樓梯間 | `in a dark apartment stairwell` |
| 電廠廠房 | `inside a power plant factory floor` |

> **範例（老張看命令紙）**：
> 前一格場景是連部收到命令紙，老張站在旁邊看，地點顯然還是連部室內。
> ❌ 省略地點 → 模型可能畫成戶外廣場或走廊
> ✅ 加一句：`in a sparse military office interior, an older soldier seen from the side looking down at something off-frame`

### 地點推斷驗證（加入驗證清單 A6）

| # | 驗證問題 |
|---|---------|
| A6 | 場景沒有明確指出地點 → 有沒有從前後文推斷地點並寫進 prompt？ |

## 規則

- **單一焦點**：一段話裡有多個動作時，只挑一個畫；不要把多個動作塞進同一張圖。
- **砍配角**：非焦點的人物/物件不要寫進 prompt（會被畫出來、干擾畫面）。
- **台詞不直接畫**：除非台詞「內容本身」就是焦點（少見，例如電視在講的話、門上紅字）。
- **角色觸發**：
  - 焦點是某角色 → `scene`/`dialogue` 要含其中文名（觸發 Block 5 的 inline 標記，並讓 generate.py 載入正確參考圖）。
  - 角色只是背景、非焦點 → **不要**寫進去，避免被畫出來。
  - **一般士兵（周下士、徐下士、黃下士、哨兵、衛生兵、下士、士兵、通訊兵等）也有對應**：這些稱謂在 `分鏡稿規範.json` 的「一般軍人」條目裡有 keyword，但**無專屬參考圖**，一律標 `(other character)`。因此：
    1. `scene` 欄位要用具體稱謂（寫「周下士」，不要只寫「士兵」）。
    2. Prompt 裡**只描述姿態/動作/位置＋最小身分識別＋`(other character)`**，不要寫細節外觀（見 Block 5 標記規則）。
- **具體可畫**：用具象、可視覺化的英文；避免抽象情緒詞當主體（情緒靠人物表情/光影傳達）。

## 全域禁止項

無論任何焦點類型，生成的提示詞**必須**在場景描述中排除以下內容：

- **字幕／文字疊加**：加入 `no subtitles, no text overlays, no captions` —— 模型在含螢幕、電視、廣播等畫面時極易自動補畫字幕或跑馬燈。
- **UI／HUD 元素**：加入 `no UI elements` —— 適用於任何含螢幕的場景。
- **電影黑邊（letterboxing）**：加入 `no letterboxing, no black bars, full bleed 16:9 frame` —— 固定風格前綴裡的 `cinematic` 字眼容易讓模型自行加上電影感的上下黑條，把畫面壓成更窄的長寬比。輸出本身已經是 16:9，不需要模型再裁一次。

> 這些禁止語應視為標準結尾格式的一部分，與 `no people visible`（物件焦點）同級，每次生成前驗證是否已加入。

## 物件焦點的額外規則

當焦點類型為「物件焦點」時，除了一般規則外，還需要：

1. **不加持有者**：除非台詞明確說某人「拿著/遞出/打開」，否則只描述物件本身，不描述誰持有它。
2. **物理狀態必須明確**：物件是放在桌上、釘在牆上、躺在地上？必須寫清楚，否則模型自行決定（常見問題：文件被畫成牆上公告）。
3. **物件尺寸/規格要具體**：`A4 sheet`、`small worn notebook`、`folded paper`，幫助模型掌握畫面佔比。
4. **加入 `no people visible`**：主動排除人物，避免模型自行補畫旁觀者。
5. **寫了 `no people visible` 就一定要加 `"no_characters": true`**：這條與「scene 裡有沒有角色名字」無關。Block 4（世界觀人物污垢）和 Block 5（角色外觀）只要沒設 `no_characters` 就會自動加，不管有沒有角色 keyword 命中——這會跟 `no people visible` 直接矛盾。判斷依據只有一個：**prompt 裡寫了 `no people visible` → 就要有 `no_characters: true`**，即使 scene 名稱完全沒提到任何角色。

> **例外**：若台詞明確說「某人推過來、某人抽出來」，可以加入「一隻手」（`a hand sliding`），但仍不描述這隻手的主人是誰。此時 prompt 仍應含 `no people visible`（排除手以外的人），`no_characters` 仍要設。

## 圖片驗證失敗時的 prompt 調整策略

**每次重生前**，先分析失敗原因並調整 prompt，再重生——不要只換 seed。根據失敗的 claim 診斷根因，從下列三個方向選擇調整策略（可組合）：

### 調整方向一：構圖/鏡頭調整

改由 **LLM 根據當前提示詞＋驗證失敗原因推論構圖方向**，再修改提示詞。

### 推論步驟

1. **診斷**：把目前生成的圖（或想像的畫面）分成兩個區域——**正確內容區域**（焦點主體、應該保留的部分）和**錯誤內容區域**（不該出現的人物、背景、環境）。
2. **找空間邊界**：這兩個區域之間是否有一條清楚的實體邊界？（例如：桌面上緣、螢幕邊框、牆壁邊緣、地面邊界）
3. **推論鏡頭位置**：如果把鏡頭推進到「邊界成為畫框邊緣」，錯誤內容區域就會被畫框切掉，物理上消失。描述這個鏡頭位置——不是「排除背景」，而是「正確內容填滿畫框，邊界就是畫框的邊緣」。
4. **修改提示詞**：用具體的畫框填充語言描述：「[主體] fills the entire frame」、「[主體的邊緣] is the edge of the frame」、「camera pushed in until only [主體] is visible」。

> **核心原則**：不要告訴模型「不要畫什麼」，而是告訴模型「鏡頭在哪裡、畫框裡只有什麼」。後者讓模型沒有空間放入不想要的元素。

### 推論範例

> **場景**：資料夾被打開，頁面特寫
> **生成結果**：資料夾和手正確，但背景有人物和辦公室空間
> **區域分析**：
> - 正確內容區域 = 桌面（資料夾和手都在桌面上）
> - 錯誤內容區域 = 桌面以外的背景空間（人物、窗戶、牆壁）
> - 兩者之間的空間邊界 = **桌面的邊緣**（桌面是一個有明確邊界的水平表面）
>
> **推論**：把鏡頭推進到「桌面填滿整個畫框，桌面邊緣超出畫框邊界」，桌面以外的空間在物理上無法進入鏡頭
>
> **提示詞修改**：`the desk surface fills the entire frame edge to edge, desk edges extend beyond the frame, no space beyond the desk is visible`

### 調整方向二：補充細節描述

當關鍵元素存在於圖中但不夠明顯，在 prompt 補上讓該元素更具體的描述。

- 例：claim 要求「傷口滲血」但圖中幾乎看不見 → 補上 `blood visibly seeping through fingers pressed against the wound`
- 例：claim 要求「紅色關防」但印章太模糊 → 補上 `a prominent red official seal stamp clearly visible on the paper`

### 調整方向三：移除錯誤描述

**僅限以下兩類情況**才移除描述，其他問題一律用改寫或構圖調整取代，不刪描述：

**可移除：**
- **場景中根本不該存在的人物**：source 未提及、Stage 2 憑空加入的背景人物數量描述（例如 `two soldiers visible in the background`，但 source 只提到一人獨處）
- **違反場景設定的物件狀態**：物件本身可以存在，但其狀態違反已知的世界設定（如停電場景中的 `streetlights casting orange glow`、全面停電後的發光螢幕等違反供電邏輯的描述）

**不可移除：**
- 氣氛填充詞、推演細節、道具具體化描述（如抽菸、皺眉、綠色資料夾）——即使圖畫得不準，用改寫或換 seed 處理
- source 或 dialogue 有明確提及的任何元素——即使難以生成，也不能為了讓驗證通過而刪除

## 天氣與陽光的情境化選擇

目前所有場景幾乎都套用同一種灰霾陰天調性（來自 Block 2 的環境描述）。但這只是**預設值**，不是唯一選項。天氣和光線是**輔助資訊**，該由這一格想傳達的情緒和敘事需求決定，而不是每格都套同一套。

> **核心原則**：先問「這一格想讓觀眾感覺到什麼」，再決定用什麼天氣/光線去支撐這個感覺——不要反過來讓天氣變成跟情緒無關的固定背景板。

### 決定天氣/光線前要問的問題

1. **語音稿有沒有明確指定晝夜？**（例如「Day 14 黎明」「Day 41 夜」「北上第 3 天」）——先看場景標題有沒有寫，有寫就照著走：日間場景不能無故變成夜景，反之亦然。
2. **這一刻的情緒方向是什麼？** 溫暖／希望的時刻 vs. 恐懼／絕望的時刻，需要的光線調性完全不同。
3. **這個天氣/光線會不會跟故事邏輯衝突？** 例如 Day 42 之後是「全面停電」設定（見 `分鏡稿規範.json` 的 power 規則），室內不會有陽光以外的光源；但戶外的日光/天氣仍不受供電邏輯限制，可以自由選擇。

### 可選的天氣/光線方向

| 方向 | 使用時機 | 寫法範例 |
|------|---------|---------|
| **灰霾陰天**（現有預設） | 大多數中性/沉重場景，維持世界剛崩潰的荒涼感 | 沿用 Block 2 環境描述的預設，不用額外寫 |
| **暖色夕陽/晨光** | 場景帶有希望、和解、决心邁向未來的情緒 | `warm golden sunlight breaking through the clouds`, `the low sun casting long warm shadows` |
| **刺眼豔陽/晴空** | 反差用途：在殘酷或荒涼的情境裡出現不合時宜的晴朗，加強諷刺或麻木感 | `harsh bright sunlight in a clear sky, the ordinary brightness of a day that shouldn't feel normal` |
| **雨** | 加重壓迫、疲憊、狼狽的情緒 | `steady cold rain, streets slick and reflecting the grey sky` |
| **濃霧** | 未知、不安、視野受限的緊張感（已用於車隊/郊野場景） | `thick fog swallowing everything beyond a few meters` |
| **夜晚（月光/黑暗）** | 由供電邏輯決定明暗程度，見 Block 3 的供電選擇；不需要在場景描述重複寫供電相關的內容 | 不用額外處理，Block 3 會自動加供電光線 |

### 範例：s91（女孩閤上筆記本朝北望）

這一格是全劇尾聲，情緒是「脆弱的希望與繼續前進的决心」——不適合套用預設的灰霾陰天。應該主動選擇暖色調：

> `walking toward a low warm sun breaking through the clouds on the horizon, the light casting long golden shadows across the empty street, fragile unexpected hope and the resolve to go on`

日光方向與情緒同步：女孩走向的方向、鏡頭裡的暖光來源，都對應著「朝希望前進」的敘事意圖。

### 規則

- **不是每一格都要指定天氣**：中性場景可以直接沿用預設灰霾陰天，不用額外寫。只有當這一格的情緒明確需要不同調性時才主動指定。
- **戶外場景才有天氣的完全自由度**：室內場景的光線由供電邏輯（Block 3）決定，不用重複寫室內光線，但仍可以透過窗戶影射戶外天氣（例如「窗外透進一絲暖光」）。
- **晝夜要跟場景標題一致**：不要因為想要某種光線效果就把日間場景改成夜景。

## 畫面情緒與觀眾感受

**每一張分鏡除了描述「看到什麼」，還要告訴模型「觀眾應該感受到什麼」。** 情緒語句寫在場景描述的最後，通常是一個簡短的英文名詞片語或形容詞組。

> 這些詞不是裝飾——它們讓模型在光影、構圖、人物表情上做出情緒一致的選擇。沒有情緒指引，模型會選最中性的詮釋。

### 怎麼決定情緒語句

從語音稿的**上下文**推斷，問：
1. **這一刻在故事裡的份量是什麼？** 轉折、悼念、希望、恐懼、決意？
2. **觀眾這時候應該有什麼感覺？** 心頭一緊、鬆了一口氣、悲從中來、毛骨悚然、茫然若失？
3. **哪一個詞/片語能最精準地傳遞這個感受？**

### 常用情緒語句索引

| 情緒方向 | 語句範例 |
|---------|---------|
| 沉重、悼念、無法逃避的代價 | `unbearable quiet`, `heavy unspoken cost`, `grief held silent`, `the weight of irreversible duty` |
| 恐懼、毛骨悚然、逼近的威脅 | `creeping dread`, `sudden cold horror`, `eerie wrongness`, `the horror of what is approaching` |
| 希望、脆弱的可能性 | `fragile unexpected hope`, `a first fragile sign of truth`, `distant uncertain sign of life` |
| 決意、孤獨前行 | `alone and resolute`, `quiet grim determination`, `the weight of command settling on him` |
| 茫然、不知所措、失去 | `devastating stillness`, `hollow absence`, `a void no action can fill` |
| 道德兩難、無法選擇 | `moral anguish`, `the weight of an impossible choice`, `a standoff with no right answer` |
| 一觸即發、緊繃 | `tense standoff`, `coiled on the edge of violence`, `a held breath before breaking` |
| 平靜裡的殘酷、日常的荒謬 | `the strange ordinariness of catastrophe`, `normality preserved inside collapse` |

### 規則

- **情緒語句接在場景描述末尾**，不單獨成句、不重複世界觀關鍵字。
- **一個畫面一個主要情緒**，不要堆疊三個以上。
- **避免直接把情緒當主語**（❌ `sadness fills the room`）；改成狀態或氛圍（✅ `grief held silent`, `devastating stillness`）。
- **弱場景也要有情緒**：即使是資訊性鏡頭（點名、推資料夾）也有它的情感溫度，只是強度低，用平靜/沉重/焦慮等較輕的詞即可。

### 範例

| 場景 | 台詞上下文 | 情緒語句 |
|------|-----------|---------|
| 少校舉槍朝天（橋上） | 我沒對人，槍口朝天，但我知道這個姿勢意味著什麼 | `moral anguish in the standoff` |
| 老李擋在門邊求帶走他 | 我不想死在這個房間 | `raw desperation` |
| 女孩抽出筆記本看名單 | 七個名字，她多停了幾秒 | `quiet grief in her eyes` |
| 筆記本推過桌面（四人名單） | 去了可能回不來，但不去更多人死 | `heavy unspoken cost` |
| 高架橋下兩人對話 | 活下去只是又一個任務 | `weary contemplative mood` |
| 北方地平線大群移動 | 整片，方向一致，往西邊去 | `awe and dread` |

## 道具・載具・設施的情境化細節

場景描述裡出現「車」「設備」「物品」等時，**根據上下文推斷它的具體樣貌**，而不是泛稱。模型畫泛稱時容易畫出民用款，情境化細節能讓畫面更貼近故事世界。

### 原則
把下列問題問完，才下筆：
1. **誰在用它？** 軍人→軍規裝備；醫護→醫院器材；警察→警用車輛。
2. **用途是什麼？** 載人軍車（troop transport truck）≠ 貨車；手術床≠ 普通床。
3. **時代／地點隱含什麼款式？** 台灣現代軍事基地常見：中型卡車、吉普車、4×4 越野指揮車、偶有裝甲人員輸送車。
4. **台詞說「很多」時，畫幾個？** 選 3–5 個，賦予差異性（不同型號、不同標記、不同狀態），讓個體質感傳達規模，而非靠數量堆疊。

### 常見情境對照

| 故事情境 | 避免泛稱 | 改用具體描述 |
|----------|----------|-------------|
| 軍事基地停車場 | `military vehicles` | `olive drab troop transport trucks, military jeeps and 4x4 command vehicles, a few armored personnel carriers` |
| 醫院大廳 | `hospital equipment` | `overturned gurneys, scattered IV stands, a nurses' station with paper charts spilled on the floor` |
| 警察封鎖線 | `police cars` | `marked patrol cruisers parked diagonally, riot shields stacked against a vehicle, yellow crime scene tape` |
| 基地補給區 | `supplies` | `wooden pallets of MRE cases, olive drab ammo cans, folded camo netting rolled against a wall` |
| 工廠／電廠內部 | `machinery` | `turbine housings, thick overhead conduit pipes, heavy steel catwalks, oil-stained concrete floor` |
| 難民區醫療站 | `medical supplies` | `folding camp cots, saline drip bags hanging from rifle barrels, blood-stained field dressings` |

> **只補焦點物件的細節**；背景裡的次要道具不用細列（`分鏡稿規範.json` 的破壞素材已處理通用廢棄感）。

## 與 `分鏡稿規範.json` 的分工

| 規範檔 | 階段 | 負責 |
|--------|------|------|
| **語音稿轉提示詞規範.md（本檔）** | 階段二 | 場景 → 完整 `prompt`（焦點描述＋block 組合判斷）＋ `claims`（驗證清單） |
| **分鏡稿規範.json** | 階段二參考 | 提供各 block 的文字內容：`common.style`（風格前綴）、`environments`（環境描述）、`power`（供電門檻與光線文字）、`characters`（角色外觀模板）、`zombie_types`（喪屍分型）、`combat`（破壞素材池） |

修正問題時：**焦點、取景、構圖、block 組合判斷**問題改本檔；**具體文字措辭**（角色外觀描述、環境描述用詞、供電門檻數值）改 `分鏡稿規範.json`。
