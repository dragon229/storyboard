# storyboard-framing｜取景設計

**輸入**：`focus` ＋ `depiction_mode` ＋ `rhetorical_function` ＋ `source`
**輸出**：`framing` 物件

**呈現手法決定用哪套詞彙**，修辭功能只做強度修正，**畫面命題 `focus` 決定版面**。

---

## 命題形狀 → 版面的硬約束 ★先跑這一節

`framing` 的欄位不是裝飾，是在告訴模型「這張圖的資訊怎麼排」。
**排錯了，命題就讀不出來**，即使 staging 每個元素都寫對了。

| 命題的形狀 | `framing` **必須** | **不可** |
|---|---|---|
| **對帳型**（同一筆錢／同一段時間的兩種用法之間的得失差） | `layout = 左右分欄`，兩邊各放帳的一邊 | 流程帶——會讀成「先這個再那個」，不是「這個換那個」 |
| **量的問句**（多少／幾／幾倍） | `layout = 置中單體` 或 `左右分欄`，其中一邊是空的 | **填 `directionality`**——見下 |
| **落差型**（以為 X 其實 Y） | `layout = 左右分欄` ＋ `contrast_balance = 失衡` | 流程帶——遞增序列會被同質化（見 staging G1） |
| **人的處境／心理** | 景別要讓人**看得出表情或動作** | `遠景` ＋ `留白`——人會縮成一個點 |

### ★量的問句不可以有方向性

`directionality`（由左至右／由上而下）等於告訴模型「這件事正在發生、而且已經完成了」。
命題是問句時，畫面要留的是一個**還沒發生的空位**——填了方向，未知就消失。

> `if_test` s14「這個匯率，到底是多少？」原本填了 `左右分欄 ＋ 均等比較 ＋ 由左至右 ＋ 對稱`，
> 畫出來是「金幣 →粗箭頭→ 一堆沙」——一個**已經換完**的交換。
> 匯率是多少這件事完全不在畫面上。使用者的原話：「應該要打一個問號是匯率是多少，
> 所以版面對比配置方向性可能都不需要」。
>
> 正解是 `置中單體 ＋ 主體突出`，其餘全部 `null`，讓那個未知自己站在畫面正中。

### ★命題主詞是人時，不可以用遠景配留白

`遠景 ＋ 留白 ＋ 鳥瞰` 這組會把人縮成畫面裡的一個小點。
它適合「規模感、孤立感」，**不適合「這個人正在做一筆虧本的交易」**。

> `if_test` s12「為了省十塊停車費，甘願繞路多開二十分鐘」原本填 `遠景 ＋ 鳥瞰 ＋ 留白`，
> 畫出來是一片空停車場加一個很小的人形走在一條弧線上。
> 帳的兩邊（省下的錢、多走的路）一邊都沒有。
> 使用者的原話：「這邊應該用對比配置。左邊花比較多的停車費，右邊是花比較少的停車費，
> 然後走很遠的路。」——對帳型命題要的是**左右分欄**，不是空景。

## 先選詞彙組

| 呈現手法 | `vocabulary` | 用哪些欄位 |
|---|---|---|
| 實景、主持人出鏡、細部放大 | `實景` | shot_size / angle / composition |
| 示意圖、並置、序列 | `圖解` | layout / info_hierarchy / directionality / contrast_balance（＋angle / composition） |
| 隱喻、尺度對照 | `混合` | 兩套都填 |

圖解詞彙是**加一層**，不是換一套——生成出來的圖解仍是一張插畫，仍有構圖與視角。

所有詞彙的實際英文寫法都在 `assets/style.json`，**逐字取用，不要自己改寫**。

## 實景詞彙

### 景別 ★最重要的一條實測結論

**景別必須用「裁切位置」描述，不能用「佔畫面幾分之幾」。**
模型讀不懂佔比，一律畫成全身小人。`style.json` 的 `shot_sizes` 已經寫成裁切句，整句照抄。

| 景別 | 什麼時候用 |
|---|---|
| 特寫 | 線索放大、單一細節承載全部資訊、極度張力 |
| 近景 | 讀表情、單一物件展示 |
| 中景 | 動作與情境的平衡點，最泛用 |
| 全身 | 需要看到完整動作或姿態 |
| 遠景 | 規模感、孤立感、世界觀建立 |

### ★選特寫／近景時必須同時填 `subject`

`style.json` 的 `特寫` / `近景` 兩條含 `{subject}` 佔位，由 `framing.subject` 填一個
**英文主體短語**（`"a bare forearm"`、`"two open palms"`、`"a single open hand"`）。
沒填 `compose.py` 會直接擋下，不會靜默通過。

為什麼要這個欄位：舊版把主體寫死成「臉」（`the face fills the frame and is cropped just
below the chin`）。但本頻道的特寫格幾乎都不是拍臉——是手、前臂、單一物件。於是 prompt
自相矛盾：同時要求「臉填滿畫框」與「兩隻手掌填滿畫框」。模型兩個都畫一半，**憑空多出一張臉
佔住畫面中央**，真正的主體被擠到旁邊。6 格特寫有 5 格這樣壞。

換成 `{subject}` 後，s59／s62／s24 三格同 seed 對照，臉全部消失、主體填滿畫框（三格三勝）。

真的要拍臉，就把 `subject` 填 `"the face"`——結果跟舊版一樣，只是這次是**你選的**。

**特寫／近景不可與構圖「留白」併用。** 一個說主體填滿畫框、一個說主體縮在角落，是直接矛盾。
需要大片空間就用中景或遠景配留白；需要主體填滿就配置中。
（基線 s35 就是這個矛盾，兩邊互相抵銷後剛好落在一個好結果上——那是運氣，不是設計。）

### ★景別與姿態必須相容（實測）

**中景只畫得下上半身能表達完的姿態。** 躺、跪、盤腿、斜靠、走動、蹲下這些是全身姿態，
中景畫不下，模型會直接退回全身景。

基線 25 格實景裡有 9 格中景被畫成全身，全部是這個原因。而且**不是拿掉「腳踝」「鞋子」
這類個別詞就能修好**——s27 把 `one ankle crossed over a knee` 整句刪掉、同 seed 重跑，
還是全身，因為「斜躺在躺椅上」這個姿態本身就要求全身畫框。

選景別時先問：**這個姿態畫成腰部以下被切掉，還讀得出他在幹嘛嗎？**

- 讀得出（坐直、傾身、雙手放桌上、舉起某物、轉頭）→ 中景可以
- 讀不出（躺、跪、走、盤腿）→ 改**全身**，或回 `storyboard-staging` 換一個姿態

### 視角

| 視角 | 感受 |
|---|---|
| 水平 | 共情、平等、觀察者立場——**預設值** |
| 俯角 | 主體顯得渺小、脆弱、被環境壓住 |
| 仰角 | 威脅感、力量、宏大 |
| 鳥瞰 | 客觀全局、疏離感，適合展示分布與陣型 |

### 構圖

| 構圖 | 效果 |
|---|---|
| 置中 | 莊重、明確、這個東西很重要 |
| 三分法 | 自然平衡，留出視線或動作空間 |
| 對角 | 動感、不穩定、衝突 |
| 框中框 | 限制感、被隔絕、在另一個世界 |
| 雙人 | 關係展示、對比 |
| 留白 | 孤獨、渺小、情緒的呼吸空間 |

## 圖解詞彙

| 維度 | 選項 | 怎麼選 |
|---|---|---|
| **版面** | 置中單體 / 左右分欄 / 上下堆疊 / 環形 / 流程帶 | 並置→左右分欄；序列→流程帶；循環因果→環形；單一概念→置中單體 |
| **資訊層次** | 主體突出 / 均等比較 | 有主從關係→主體突出；平等比較→均等比較 |
| **方向性** | 由左至右 / 由上而下 / 由下而上 / 匯聚 / 發散 | 時間流向與因果流向；沒有方向性就不填。**一格只能有一個方向**，見下 |
| **對比配置** | 對稱 / 失衡 | 平等比較→對稱；一方壓倒另一方→失衡。**填了「失衡」不代表模型會畫歪**，見下 |

### ★兩條圖解版面的實測限制

**一格只能有一個方向。** 模型無法讓同一張圖裡兩個同類元素帶相反方向——方向會被同質化成
一個，翻到哪邊隨機。要表達「一升一降」不能用兩支反向箭頭（實測必壞），改用**位置高低編碼**；
要表達「雙向互換」改用 `layouts.環形`。詳見 `storyboard-staging` 的 G1。

**`contrast_balance: 失衡` 只是版面提示，不會讓模型把天平畫歪。** 失衡必須由
`storyboard-staging` 寫成幾何事實（哪一盤在下緣附近、哪一盤在上緣附近），
只填這個欄位會畫成水平。詳見 G3。

## 修辭功能的強度修正

功能不決定取景，但會調整強度：

| 功能 | 修正 |
|---|---|
| 拋出鉤子 | 往**極端**推——最特寫或最遠景、最大留白。平庸的中景殺不出懸念 |
| 點出直覺 / 推翻 | **兩格必須同景別、同視角、同構圖**，只有內容相反。這是跨格硬約束，見 `storyboard-depiction` |
| 佐證 | 往**清晰可讀**推——不要炫技構圖，觀眾要能一眼確認「這是真的」 |
| 推進 | 往**開闊**推——推演是往外展開，畫面別鎖太死 |
| 收束 | 呼應第一格的取景，形成閉環 |

## 全域禁止文字：對取景的影響

畫面**不能出現任何文字**（見 `storyboard-compose`）。這件事會反過來限制取景：

- 不要選一個「非得靠標籤才讀得懂」的版面。如果你發現這個構圖不標字就看不懂，**換構圖**。
- 資訊要靠**視覺編碼**承載：顏色、形狀（實心／空心）、大小、密度、箭頭方向、明暗。
- 真的需要專有名詞時，選一個**留有明顯空白區域**的版面，該格標 `needs_post_text`，字後製加。

> 這條限制會逼出更好的圖。不能寫「這是負電荷」，就得讓畫面自己說明——用一整片藍色密集
> 小點，觀眾不用讀字就知道那裡「有很多某種東西」。

## 輸出

```json
"framing": {
  "vocabulary": "圖解",
  "shot_size": null,
  "subject": null,
  "angle": "水平",
  "composition": "置中",
  "layout": "左右分欄",
  "info_hierarchy": "均等比較",
  "directionality": null,
  "contrast_balance": "對稱"
}
```

用不到的欄位填 `null`，不要省略。
**`shot_size` 填「特寫」或「近景」時 `subject` 必填**（英文主體短語）：

```json
"framing": { "vocabulary": "實景", "shot_size": "特寫", "subject": "a bare forearm", ... }
```

逐格處理，寫完立刻存回 `output/<系列>/<系列>.json`。
