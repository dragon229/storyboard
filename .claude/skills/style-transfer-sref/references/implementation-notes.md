# style-transfer-sref 實作筆記

研究過程完整紀錄在 `research/sref-lora/log.md`。這裡只放「要改這個 skill 之前必須知道的事」。

## 權威來源

model card 沒有 trigger word、沒有推薦權重、沒有推論範例——**唯一有用的是 repo 附的
`qwen_image_edit_2509_vl_sref.json`**。所有參數都是從那個檔逐節點讀出來的。

讀那個檔時要注意三件事：

1. **它是 UI 格式**（`nodes` / `links`），不能直接送 `/prompt` API
2. **超過一半節點 `mode=4`（bypass）**，那是另一條「多圖 + raw latent」的分支，不是這條路
3. **節點 111 的 widget 裡有一段寫死的舊 prompt**（黑貓變小狗）。它的 `prompt` 輸入有連線會蓋掉 widget——那段文字是死資料

## 為什麼 VLM 搬到 ComfyUI 外面

官方用 `AILab_QwenVL`（ComfyUI-RMBG 附的自訂節點），本機沒裝，`/object_info/AILab_QwenVL` 回 `{}`。

沒有去裝它，是刻意的：

- 少一個自訂節點相依
- **VLM 寫的指令必須人工複核**，包在 ComfyUI 裡就看不到、改不了
- 有 `data/sref_prompts.json` 快取，同一組（圖, 題材）不用重跑

代價：模型不同（Qwen2.5-VL-7B vs 官方 Qwen3-VL-4B），指令風格有差——官方範例是長串破折號條列、緊扣風格；7B 傾向數字條列、偏短、而且會自己發明場景。護欄就是在補這個。

## 護欄（`_GUARD`）是本 skill 加的，不是官方原文

官方那段指令是配 Qwen3-VL 調的。換成 Qwen2.5-VL-7B 後它守不住「只严格描述在同一画风下的编辑」，
實測寫出「替换为一个简单的白色背景」「如草地或公园」，出圖直接毀掉。

`--no-guard` 可以退回官方逐字原文（做對照實驗用）。

護欄有效但不完美——7B 仍偶爾寫出「调整颜色使其符合自然颜色」這種違反護欄的句子，
**所以 SKILL.md 步驟 2 的人工複核不能拿掉**。

## 實驗數據（2026-08-05）

三個性質不同的風格參考圖，題材固定，比較各條件下的統計量。
`L`＝亮度、`暖`＝R−B、`S`＝飽和、`殘留`＝與參考圖的構圖相似度。

### style_ref_1（平塗賽璐璐 anime，參考 L36 暖−26 S0.79）

| 條件 | L | 暖 | S | 銳利 | 殘留 |
|---|---|---|---|---|---|
| 只給名詞 + sref | 57 | −12 | 0.80 | 51.1 | 0.169 |
| 只給名詞，**無 sref** | 55 | −12 | 0.82 | 50.8 | 0.193 |
| VLM 指令 + sref | 49 | +36 | 0.87 | 42.8 | 0.109 |
| VLM 指令，**無 sref** | 53 | +39 | 0.88 | 43.9 | 0.091 |

**只給名詞時，開不開 sref 幾乎沒差**——那條路走的是底模原生編輯能力，測不出 LoRA。
這是「樣本不夠格」的典型：不是 LoRA 沒用，是測試方式顯示不出來。

### style_ref_4（3D 黏土公仔，參考 L65 暖+38 S0.52）

| 條件 | L | 暖 | S | 殘留 | 目視 |
|---|---|---|---|---|---|
| VLM 指令 + sref | 110 | +47 | 0.63 | 0.018 | 光滑塑料質感、大眼高光 → **畫風保住** |
| VLM 指令，**無 sref** | 102 | +43 | 0.64 | 0.023 | 寫實毛髮照片 → **畫風掉了** |
| **護欄** + sref | 81 | +57 | 0.63 | 0.594 | 吊燈、暗色室內、三個公仔女孩全留著 → 最佳 |

**這組才是 LoRA 有效的證據。** 統計量幾乎一樣（L 110 vs 102），但目視差異巨大——
典型的「數字不能取代眼睛」。

### style_ref_6（顆粒感綠調底片，參考 L69 暖−11 S0.69）

| 條件 | L | 暖 | S | 殘留 | 目視 |
|---|---|---|---|---|---|
| VLM 指令 + sref | 203 | +6 | 0.23 | 0.138 | 整片漂白，風格全毀 |
| VLM 指令，**無 sref** | 219 | +7 | 0.14 | 0.142 | 同上，更糟 |
| 手寫指令 + sref | 84 | −31 | 0.77 | 0.110 | 隧道／綠調／顆粒回來了 |
| **護欄** + sref | 95 | **−10** | 0.72 | 0.124 | 暖度幾乎命中參考值（−11）→ 最佳 |

單變因實驗：**只改 prompt、其他全不動，L 從 203 掉到 95、S 從 0.23 回到 0.72。**
根因＝VLM 指令，不是 LoRA。

## 雙圖模式（content 圖 + style 圖）的實驗

需求變更後補做的。結論：**雙圖風格轉換的能力不在 sref LoRA 裡，在 qwenstyle LoRA 裡。**

### 靜默失效：sref 單掛時 image2 完全無效

content 固定為 style_ref_1（賽璐璐 anime），prompt 固定，只換風格圖：

| 風格圖 | 風格圖的 L / 暖 / S | 輸出 L / 暖 / S |
|---|---|---|
| style_ref_4 | 65 / +38 / 0.52 | 34 / −25 / 0.85 |
| style_ref_6 | 69 / −11 / 0.69 | 34 / −23 / 0.80 |
| style_ref_2 | **180 / −1 / 0.07**（近乎白圖） | 34 / −24 / 0.85 |

三張性質天差地遠的風格圖，輸出**完全相同**。image2 零影響。
拿掉 sref LoRA（純底模）結果一樣（L35 暖−28）。中文與英文 prompt 措辭都試過，沒差。
節點的 optional 插槽名稱查證過確實是 `image1/image2/image3`，接線沒錯。

### 單變因：只換 LoRA

同一條線、同樣的圖與 prompt，只把 sref 換成 `qwenstyle_v1_2509_diffusers`：
輸出 L 從 34 變 55，目視手部從線稿變成光滑 3D 塑料質感。**風格確實進去了。**

→ 接線正確；缺的是那顆 LoRA。

### 兩顆疊加（定案作法）

`UNET → sref → qwenstyle → Lightning`，prompt 用 QwenStyle 官方英文原句：

| 風格圖 | 疊加（構圖保留 / L） | 只用 qwenstyle | 目視 |
|---|---|---|---|
| ref_4 3D 公仔 | **0.547 / 43** | 0.386 / 55 | 疊加：光滑塑料質感、構圖完整；qwenstyle 單掛較糊 |
| ref_2 漫畫網點 | **0.171 / 68** | 0.220 / 66 | 疊加：乾淨漫畫排線；**qwenstyle 單掛把手臂畫成鵝卵石亂紋（失敗）** |
| ref_6 底片顆粒 | 0.404 / 29 | 0.255 / 44 | 兩者都幾乎沒轉過去 |

三個案例：2 個明顯成功、1 個（照片類風格）幾乎無效。**照片類風格是已知弱項。**

### 文字通道（`--text-bridge`）

VLM 把 content 圖描述成純內容文字（指令明令禁止提畫風，避免跟風格圖打架），
再走 sref 原生單圖流程。

實測 content=ref_1、style=ref_4：風格確實轉過去（手變 3D 光滑、人物變 3D 剪影），
但**構圖保留只有 0.031**——手的位置變了、裝置變成手機、人物變成上班族。
而且輸出比例跟風格圖走，不是內容圖。

→ 只當備案。content 經過文字必然掉資訊。
