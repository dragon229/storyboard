# storyboard-verify-image｜圖片核對（甲）

**輸入**：圖片 ＋ 該格 `prompt`
**輸出**：不符合的項目清單

問的是「**模型有沒有畫出我叫它畫的東西**」，不是「我叫它畫的東西對不對」——後者是
`storyboard-verify-draft` 的事。

---

## 作法：圖與 prompt 一起看，直接找不符項

**不預先產 claims 清單。** 由生成端產 claims 是自己出考題給自己考——claims 跟 prompt
是同一次思考的產物，生成時漏掉的東西 claims 也會一起漏掉，兩邊同時錯就會驗證通過。

詳見 `docs/adr/0002-blinded-verification.md`。

---

## 必走的兩步（順序不可省）

**這種問法有一個已知弱點：對「多了不該有的東西」很敏感，對「少了該有的東西」較遲鈍**
——看圖時，缺席的東西不會主動跳出來喊。所以：

### 第一步：先讀 prompt，逐項列出它要求了什麼

**在看圖之前做。** 把 prompt 拆成一條條具體要求：

```
prompt: "medium shot, the subject cropped at the waist... three devices of
different sizes standing on a table, each with a different arrangement of
knobs and indicator lights..."

要求：
  1. 中景，主體在腰部被下緣裁切
  2. 三個裝置
  3. 三個大小明顯不同
  4. 站在桌面上
  5. 每個的旋鈕與指示燈配置不同
  6. 畫面無文字
```

### 第二步：逐項看圖確認

一項一項對，每項判「是／否」。**圖中沒有明確呈現的，一律判「否」**——不要因為
「看起來大概有」就放過。

---

## 額外必查的四類

不管 prompt 寫了什麼，這四類每張都要看：

| # | 檢查 | 為什麼 |
|---|---|---|
| E1 | **有沒有出現文字？** 招牌、螢幕、標籤、數字、任何像字的筆畫 | 本頻道全域禁止文字。模型寫出來的是亂碼，比沒標籤更糟 |
| E2 | **景別對不對？** 特別是特寫格有沒有變成全身小人 | 最常跑掉的一項。常見原因是 prompt 提到了鞋子或全身姿態 |
| E3 | **角色長相有沒有走鐘？** 圓頭、翹髮、圓框眼鏡、點狀眼、腮紅、赭紅主色 | 一致性是頻道命脈 |
| E4 | **有沒有左右分割的拼貼構圖？** 畫面被切成兩半、像兩張圖拼起來 | 已知會出現的模型失誤 |

還有兩類物理現實問題，出現就判否：

- **人體異常**：頭身方向差超過 90 度、四肢數量錯誤、五官位置錯位
- **空間矛盾**：物體浮在背景上、重力方向矛盾、人與物互相穿插（而非遮擋）

---

## 診斷：為什麼沒畫出來

回報時附上根因判斷，讓下游知道該怎麼修：

| 症狀 | 多半是 | 怎麼修 |
|---|---|---|
| 元素完全沒出現 | prompt 沒寫清楚，或被其他描述蓋過 | 回 `storyboard-staging` 補描述 |
| 元素出現但不明顯 | 描述太籠統 | 補具體化的描述 |
| 景別跑掉 | prompt 內部矛盾（寫了超出畫框的東西） | 回 `storyboard-compose` 檢查 B4 |
| 多出不該有的人物或元素 | prompt 憑空加了原文沒有的東西 | 回 `storyboard-staging` 刪掉 |
| 全部都對但就是畫得不好 | 單純 seed 運氣 | 換 seed 重生 |

**只有最後一種該換 seed。** 其他四種換 seed 沒用，會浪費一輪。

---

## 輸出

```
s12  ✗ 不符 3 項
     ・要求三個裝置，圖中只有兩個
     ・要求大小明顯不同，圖中兩個大小相近
     ・E1 圖中右下角有疑似文字的筆畫
     診斷：數量與差異性描述太籠統 → 回 staging 補具體化
```

**不要自動重生。** 只報告，讓使用者決定要修哪幾格。
