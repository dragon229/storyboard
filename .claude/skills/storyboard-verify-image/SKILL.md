# storyboard-verify-image｜圖片核對（甲）

**輸入**：圖片 ＋ 該格 `prompt`
**輸出**：不符合的項目清單

問的是「**模型有沒有畫出我叫它畫的東西**」，不是「我叫它畫的東西對不對」——後者是
`storyboard-verify-draft` 的事。

---

## 作法：圖與 prompt 一起看，直接找不符項

**不預先產 claims 清單。** 由生成端產 claims 是自己出考題給自己考——claims 跟 prompt
是同一次思考的產物，生成時漏掉的東西 claims 也會一起漏掉，兩邊同時錯就會驗證通過。

詳見 `docs/adr/0002-blinded-verification.md`。

---

## 必走的兩步（順序不可省）

**這種問法有一個已知弱點：對「多了不該有的東西」很敏感，對「少了該有的東西」較遲鈍**
——看圖時，缺席的東西不會主動跳出來喊。所以：

### 第一步：先讀 prompt，逐項列出它要求了什麼

**在看圖之前做。** 把 prompt 拆成一條條具體要求：

```
prompt: "medium shot, the subject cropped at the waist... three devices of
different sizes standing on a table, each with a different arrangement of
knobs and indicator lights..."

要求：
  1. 中景，主體在腰部被下緣裁切
  2. 三個裝置
  3. 三個大小明顯不同
  4. 站在桌面上
  5. 每個的旋鈕與指示燈配置不同
  6. 畫面無文字
```

### 第二步：逐項看圖確認

一項一項對，每項判「是／否」。**圖中沒有明確呈現的，一律判「否」**——不要因為
「看起來大概有」就放過。

---

## 額外必查的四類

不管 prompt 寫了什麼，這四類每張都要看：

| # | 檢查 | 為什麼 |
|---|---|---|
| E1 | **有沒有出現文字？** 招牌、螢幕、標籤、數字、任何像字的筆畫。**時鐘面、鈔票、硬幣正面要放大看** | 本頻道全域禁止文字。模型寫出來的是亂碼，比沒標籤更糟。這三個物件會自己長出數字／`$`，寫 `blank-faced` 也擋不住 |
| E2 | **景別對不對？** 特寫格有沒有變成中景／全身；中景格有沒有變成全身 | 最常跑掉的一項。特寫看 `framing.subject` 有沒有真的填滿畫框；中景看姿態是不是躺／跪／走動（那些畫不下） |
| E2b | **有沒有憑空多出一張臉？** prompt 的主體是手／前臂／物件，但畫面中央出現一張臉 | 舊版景別句把主體寫死成「臉」的後遺症。改用 `{subject}` 後應該不再出現，出現就是 `framing.subject` 沒填 |
| E3 | **角色長相有沒有走鐘？** 圓頭、翹髮、圓框眼鏡、點狀眼、腮紅、赭紅主色 | 一致性是頻道命脈 |
| E4 | **有沒有左右分割的拼貼構圖？** 畫面被切成兩半、像兩張圖拼起來 | 已知會出現的模型失誤 |

### 圖解格另外三項必查（照順序，別跳）

這三項是圖解格最常壞的地方，而且**看圖時不會主動跳出來喊**：

| # | 檢查 | 怎麼看 |
|---|---|---|
| **F1 同質化** | 找出畫面裡「兩個以上長得一樣的東西」，逐一比對它們該不該一樣 | 最高頻的失效。箭頭方向、秤盤內容、面板填充程度——只要 prompt 要求同類元素之間有差異，就要實際去看差異在不在。**沒有差異 = 判否，而且要回 staging 改呈現方式，不是改措辭** |
| **F2 數量** | prompt 講了幾個，圖上就數幾個 | 抽象色塊／長條／圓點最常錯。**逐個數，不要目測** |
| **F3 缺席** | 把 prompt 點名的元素列成清單，一個一個在圖上找 | 次要元素（伸過來的手、旁邊的桶子、背景的門階）與**純抽象形狀**（`a plain pale bar`、`a blank card`）最容易整個不見 |

還有兩類物理現實問題，出現就判否：

- **人體異常**：頭身方向差超過 90 度、四肢數量錯誤、五官位置錯位
- **空間矛盾**：物體浮在背景上、重力方向矛盾、人與物互相穿插（而非遮擋）

## 診斷：為什麼沒畫出來

回報時附上根因判斷，讓下游知道該怎麼修：

| 症狀 | 多半是 | 怎麼修 |
|---|---|---|
| 元素完全沒出現 | 它是次要元素被主體吃掉，或它是純抽象形狀 | 回 `storyboard-staging`：把它寫到句首、給明確入畫位置（G「次要元素」節）；抽象形狀要先給它語義（G5） |
| 元素出現但位置錯／併進主體裡 | 用了 `against` / `beside` / `between` 這類關係詞 | 改寫成畫面座標或容器（G2） |
| 箭頭方向反了 | 這一格有兩個相反方向，被模型同質化 | **改措辭沒用**。回 `storyboard-staging` 改成位置編碼或環形（G1） |
| 該傾斜／失衡的畫成水平 | 失衡只寫在 `contrast_balance` 欄位，沒寫成幾何 | 回 staging 寫「哪一邊在上緣、哪一邊在下緣」（G3） |
| 數量不對 | 抽象幾何元素用了數詞 | 改成質性差異詞（single vs cluster），或換成有語義的實體（G4） |
| 景別跑掉（中景變全身） | 姿態本身要求全身畫框 | **刪掉「鞋子／腳踝」救不回來**。回 `storyboard-framing` 改景別，或回 staging 換姿態 |
| 憑空多出一張臉 | `framing.subject` 沒填 | 回 `storyboard-framing` 填主體短語 |
| 多出不該有的人物或元素 | prompt 憑空加了原文沒有的東西 | 回 `storyboard-staging` 刪掉 |
| 全部都對但就是畫得不好 | 單純 seed 運氣 | 換 seed 重生 |

**只有最後一種該換 seed。** 其他每一種換 seed 都沒用，會浪費一輪。

> 反過來說：**方向錯、數量錯、抽象元素消失這三種是機率型的**——同一個 prompt 換 seed
> 有時會對。不要因為重跑一次剛好對了就以為 prompt 沒問題，那只是這一次沒中。

## 輸出

```
s12  ✗ 不符 3 項
     ・要求三個裝置，圖中只有兩個
     ・要求大小明顯不同，圖中兩個大小相近
     ・E1 圖中右下角有疑似文字的筆畫
     診斷：數量與差異性描述太籠統 → 回 staging 補具體化
```

**不要自動重生。** 只報告，讓使用者決定要修哪幾格。
