# storyboard-intent｜段落意圖判讀

**輸入**：分鏡格的 `source`（＋前後各一格當上下文）
**輸出**：`focus` / `rhetorical_function` / `emotional_shift` / `is_speculation`

一次閱讀得到四個結論。不要分四次讀——分開判會互相打架
（功能判成「收束」、情緒判成「初次的好奇」，自相矛盾）。

**`focus` 要先寫，而且是整條流程最重要的一個欄位。** 下游三支 skill
（depiction / framing / staging）全部吃它，不吃 `source`。

---

## 零、畫面命題 `focus` ★整條流程的地基

**問的是：觀眾看完這一格，會知道哪一件事。**

寫成一句**完整的中文句子**，填進這個空格：

> 觀眾看完這一格會知道：__________。

### 三條硬規則

**F1 必須是句子，不能是名詞片語。**

| ✗ 名詞片語 | ✓ 命題 |
|---|---|
| 計程車、掃地、代排隊 | 錢**換掉**了站在站牌前乾等的那段時間 |
| 一年生命的價格 | **你的**一年生命被標價四十九萬美金 |
| 機會成本 | 你閒晃掉的半天，不是沒賺到五塊，是實實在在**虧掉**五塊 |
| 兩隻手、摸得到與摸不到 | 你**想像不出來**，省下的那兩個鐘頭到底值多少錢 |

**F2 命題的主詞就是畫面的主體。**
主詞是「你／他／人的處境或心理」→ **畫面必須有一個人**，不可以只畫物件。
主詞是「錢／時間／某個概念」→ 才可以純物件。

**F3 命題不是 `source` 的摘要，是這一格相對於鄰格**新增**的那件事。**

`source` 通常是「鋪陳 + 落點」，而且相鄰幾格常常在講同一個大主張的不同面向。
**寫摘要，相鄰格會全部壓出同一句話；寫「新增的那件事」，每格才會不同。**

這條跟 `storyboard-segment` 的 B2（命題與前 2 格重複 → 併格）是同一件事的兩面：
- 找得出各自新增的東西 → 各自成格，命題就寫那個增量
- 找不出來 → 這一格本來就該併掉

> **實例（`if_test` s18 / s19，兩格緊鄰、功能都是佐證、大主張也一樣）：**
>
> 兩格的 `source` 都落在「買時間比買東西更快樂」。寫摘要的話兩格一模一樣。
> 寫增量才分得開：
>
> - s18 新增的是**規模與權威**（2017、國家科學院、跨四國、六千人）
>   → 命題「這件事有一個跨四國、六千人的研究撐腰」
> - s19 新增的是**對照實驗的設計**（同一群人、兩個週末、一樣多的錢）
>   → 命題「同一群人拿同樣的錢，買時間比買東西更快樂」
>
> 這個差別直接決定下游：s19 的命題是對帳型（要畫兩邊，實際也畫了左右兩組人）；
> s18 的不是（畫陽台喝咖啡＋背景清潔工就成立）。
> **若把 s18 的命題也寫成比較句，下游會要求它畫出一個不存在的對照組——
> 本來對的格會被判成錯的。**

修辭功能會**提示**落點的形狀（不是硬規則，衝突時以「增量」為準）：

| 修辭功能 | 落點通常是 |
|---|---|
| 拋出鉤子 | 那個想不通的現象——不要寫成解釋，好奇心會當場死掉 |
| 點出直覺 / 推翻 | 兩者的差——寫成單邊，對比就整個消失 |
| 佐證 | 「這是真的」的那個依據 |
| 推進 | 推出來的那一步，常常是一個問句 |

（這一欄只填**修辭功能**的九項。「並置」「示意圖」那些是呈現手法，
兩軸不可混填——見 `CONTEXT.md` 的「撞名」。）

### 為什麼非要這一欄（2026-08-07 實測）

`CONTEXT.md` 一直定義著「焦點」——「一格裡最該讓觀眾看到的那一件事，判準是**看到**而非**聽到**」
——但整條流程從來沒有任何一步產出它。`storyboard-staging` 的輸入直接是整段 `source`。

**結果是 staging 退化成「從 source 裡挑最顯眼的可畫名詞」。**
名詞清單 ≠ 命題，所以只要重點不落在名詞上，畫面就失焦：

| 重點落在哪 | 挑名詞會畫成 | 壞掉的格 |
|---|---|---|
| **動詞**（換／虧／賠／比） | 三個靜物並排 | s07 s11 s12 |
| **問句**（要多少錢？） | 一個已完成的陳述 | s08 s14 |
| **主詞是人的處境／心理** | 一組物件隱喻 | s02 s24 |
| **「以為 X，其實 Y」的落差** | 只畫了 Y | s23 |

`if_test` 前 24 格逐格稽核：**12 格「命題＝字面名詞」的全部通過，
12 格「命題≠字面名詞」的全部被使用者標為畫錯重點。0 反例。**
且在圖解格內部一樣完美分開（s03/s13/s17/s19 通過，其餘 11 格全壞），
不是「實景比較好畫」的共變。

### 命題寫不出來怎麼辦

**寫不出一句完整命題，或寫出來的命題與鄰格重複 → 這一格不該存在。**
回 `storyboard-segment` 併格，不要硬湊一張圖。詳見該 skill 的「命題覆蓋檢查」。

三種典型（`if_test` 實例）：

| 形狀 | 例子 | 處置 |
|---|---|---|
| **換句話說** | s06「換句話說，你花錢把時間買回來了」——命題與 s05 完全相同 | 併入 s05 |
| **目錄式** | s15「拿錢換時間其實有兩種」——內容被 s16 + s17 逐一覆蓋 | 併入 s16 |
| **目錄式** | s21「擋在中間的坎不只一道」——內容被 s22–s24 逐一覆蓋 | 併入 s22 |

> ⚠ **「聽起來像預告」不是判準，「內容被後續逐一覆蓋」才是。**
> s03「今天我們來認真算一件事：錢能不能買到時間？」也有目錄味，但它拋出的是全片的核心問句，
> 下一格（外送費）沒有覆蓋它 → **保留**。這條例外寫得太寬的話，目錄式判準會整個失效。

### `focus` 與 `rhetorical_function` 的分工

| | 層級 | 同一 `unit` 的多格 |
|---|---|---|
| `rhetorical_function` | **論述單元**層級 | 填**同一個**值 |
| `focus` | **格**層級 | 每格**必須不同**——相同就是該併格 |

## 一、修辭功能（9 選 1）

**問的是：這一段對觀眾的認知做了什麼。**

| 功能 | 對觀眾做的事 | 例子 |
|---|---|---|
| **拋出鉤子** | 製造好奇，先不解釋 | 「閃電的溫度是太陽表面的五倍。」 |
| **建立前提** | 給接下來需要的已知 | 「先講一件事：空氣其實不導電。」 |
| **點出直覺** | 說出觀眾心裡本來的預設 | 「直覺上你會覺得，閃電是從天上打下來的。」 |
| **推翻** | 揭示那個預設錯在哪 | 「但你看到的那道光，其實是從地面往上竄的。」 |
| **拆解機制** | 解釋它實際怎麼運作 | 「雲底累積負電荷，地面被感應出正電荷…」 |
| **佐證** | 用例子／數據／實驗撐住主張 | 「1971 年有人用每秒兩萬張的攝影機拍下全程。」 |
| **推進** | 從已建立的往下推一步 | 「所以如果空氣要被電離才導電，那電壓就得高到某個門檻。」 |
| **敘事** | 講一段過程，讓觀眾跟著走 | 花 40 秒講富蘭克林淋著雨、鑰匙冒火花、伸手去碰 |
| **收束** | 下結論、講意涵 | 「這就是為什麼閃電是彎的——它是被摸索出來的。」 |

### 兩條必守的規則

**1. 功能由「位置」決定，不由「內容」決定。**

同一則素材，放在不同位置就是不同功能：

| 富蘭克林放風箏出現在哪 | 功能 |
|---|---|
| 開場第一句，然後切正題 | **拋出鉤子** |
| 講完電位差原理之後補一句「1752 年他證明了這件事」 | **佐證** |
| 花 40 秒講他淋雨、鑰匙冒火花、差點電死 | **敘事** |

**所以判讀一定要看上下文。只看這一段判不出來。**

**2. 功能是「論述單元」層級的屬性。**

同一個 `unit` 的所有格，填**同一個**功能值。不要因為切成三格就想把它們判成三種功能。

## 二、情緒偏移

頻道基調是**輕鬆好奇**（常數，寫在 `assets/style.json`）。這裡只判**相對於基調的偏離**。

**大多數格沒有偏移** → 填 `null`。不要為了填而填。

有偏移的通常是這幾個位置：

| 位置 | 典型偏移 |
|---|---|
| 拋出鉤子 | **懸念** ——「如果…」句型天生帶懸念，這格該是全片最暗、最留白、最想不通的一張 |
| 推翻 | **意外** ——「欸？」的那一瞬間 |
| 收束 | **恍然** 或 **餘韻** |
| 敘事的高潮 | 依內容（緊張、荒謬、感慨） |

情緒偏移最後會變成 prompt 尾端的一個英文片語。避免直接把情緒當主語
（✗ `sadness fills the room`），改成狀態或氛圍（✓ `a held breath before the answer`）。

## 三、是否為推演

**布林值。判斷這一格畫的是「確實發生過的」還是「推測的」。**

判斷依據就是修辭功能，不需要另外思考：

| 修辭功能 | `is_speculation` |
|---|---|
| 佐證、建立前提、敘事、拆解機制 | `false`（真實錨點） |
| 推進 | `true`（推演） |
| 拋出鉤子、點出直覺、推翻、收束 | **看內容**——講真實現象是 `false`，講假設世界是 `true` |

這個欄位會讓 `storyboard-compose` 套上「推演調性」，讓觀眾分辨得出真假。
判錯的後果是觀眾把推測記成事實——對科普頻道是硬傷，寧可保守標 `true`。

> **反事實影片的骨架是「錨定真實 → 推演虛構」的交替。** 「如果沒有科幻小說」之所以成立，
> 是因為能指出真實發生過的事（翻蓋手機抄 Star Trek 的通訊器）。判讀時留意這個節奏——
> 若連續十格都是 `true`，多半是漏判了中間的真實錨點。

## 輸出

逐格讀 `output/<系列>/<系列>.json`，填四個欄位，**立刻寫回同一個檔**，再讀下一格。
不要在記憶裡累積已完成格的內容。

```json
{
  "id": "s07",
  "focus": "錢換掉了站在站牌前乾等的那段時間。",
  "rhetorical_function": "拆解機制",
  "emotional_shift": null,
  "is_speculation": false
}
```

`focus` 用**中文**寫，且必須是完整句子（結尾是句號或問號）。它不會直接進 prompt——
它是給 depiction / framing / staging 三支 skill 讀的指令。

跑完回報：
1. 各功能的分布（例：`推進 18、佐證 9、拆解機制 7…`）
2. **寫不出命題、或命題與鄰格重複的格**——這些要退回 `storyboard-segment` 併格，逐格列出理由
本頻道定位是「推演的樂趣」，**推進應該是最高頻的功能**；若拆解機制遠多於推進，
多半是判讀偏了，回頭檢查。
