Qwen_Image_Edit_2509_Sref_Lora 研究報告 01

2026-08-05 · 產出 skill style-transfer-sref · 日誌見 log.md

一句話結論：這顆 LoRA 做的是「用參考圖的畫風畫一個新題材」，不是「把我的圖轉成那個風格」。 它確實有效，但只有在餵長篇中文編輯指令時才顯現；失敗幾乎都出在那段指令的品質，不在模型。

1 · 這不是 qwenstyle

style-transfer-qwenstylestyle-transfer-sref（本次）
輸入content 圖 + style 圖只有 style 圖 + 中文題材詞
保留content 的構圖／人物／物件只保留畫風，題材換掉
典型指令「把這張轉成那個風格」「用這個風格畫一隻粉色八爪魚」

model card 的英文寫 "style transfer"，很容易誤判成同一件事。實際輸入形態完全不同。

2 · 陷阱：只給名詞，測不出這顆 LoRA

參考圖是平塗賽璐璐 anime，題材「粉色八爪鱼」。prompt 只給名詞時，開不開 sref 幾乎同圖：

一度判定「LoRA 沒生效」。實際上是測試素材不夠格——短 prompt 走的是底模 2509 原生的 編輯能力，根本沒踩到 LoRA 的訓練分佈（風格圖 + 長篇編輯指令）。

3 · 對照組：LoRA 確實有效，但要睜眼看

3D 黏土公仔風格，題材「一只戴帽子的柴犬」，兩邊用同一段 VLM 指令：

統計量幾乎一樣（L 110 vs 102、S 0.63 vs 0.64），目視是「公仔」vs「寫實照片」。 只看數字會判定「沒差」。這就是為什麼每輪都必須抽樣看圖。

4 · 根因：VLM 指令，不是模型

顆粒感綠調底片風格。VLM（Qwen2.5-VL-7B）自己寫出替换为一个简单的白色背景， 出圖直接漂白：

只改了那段文字，L 從 203 掉到 84、S 從 0.23 回到 0.77。隧道、綠調、顆粒、暗角全部回來。 根因確定在 prompt。

5 · 修正：護欄

官方那段指令是配 Qwen3-VL 調的，Qwen2.5-VL-7B 守不住。在後面接一段硬約束（_GUARD）， 禁止「純色背景／更換場景／還原成自然顏色／新增裝飾物」：

風格圖無護欄有護欄參考值
ref_6L203 暖+6 S0.23L95 暖−10 S0.72L69 暖−11 S0.69
ref_4L110 暖+47 殘留0.018L81 暖+57 殘留0.594L65 暖+38

護欄不完美——7B 仍偶爾寫出「调整颜色使其符合自然颜色」這種違反護欄的句子。 所以 skill 裡「人工複核編輯指令」那步不能拿掉。

6 · 驗收：三個性質不同的案例

案例性質結果
style_ref_1平塗賽璐璐 anime、霓虹賽博通過（硬邊平塗＋描線保住）
style_ref_43D 黏土公仔、暖色吊燈室內通過（塑料質感＋場景保住）
style_ref_6顆粒感綠調底片、失焦暗角通過（隧道＋綠調＋顆粒保住）

7 · 結論的界線

  • 結論建立在「VLM 指令品質夠好」的前提上。指令品質是輸出品質的硬上限。
  • 短 prompt 測不出這顆 LoRA。拿短 prompt 說「這 LoRA 沒用」，那個結論不成立。
  • 未驗證：7000 以外的 28 顆 checkpoint、--strength ≠ 1.0、2511 底模、官方的 Qwen3-VL-4B。

8 · 繞路與更正

  • 先做的煙霧測試用短 prompt，得到「LoRA 好像沒生效」的錯誤印象，走了一段冤枉路。 更正方式是換上長指令重測，不是調參數。
  • 官方 workflow 是 UI 格式且一半節點 bypass，直接匯入會缺 AILab_QwenVL 節點。 改成把 VLM 搬到 ComfyUI 外面——結果更好，因為指令才能被人工複核。
  • 官方 workflow 節點 111 的 widget 裡有一段寫死的舊 prompt，執行時被連線覆蓋。 差點照抄那段死資料。
