風格轉換 workflow 實驗報告 03

工程迭代輪｜主題：改接線、改輸入、改架構，逼出「圖驅動」的風格轉換｜目標值 L 203 / 暖 +72 / S 0.32｜2026-08-04～05

本輪新增的量測工具

前兩份報告全靠人工看圖，效率太低也容易漏。本輪加了兩個自動指標：

  • 內容分數：輸入與輸出的 Sobel 邊緣圖正規化互相關（0–1）。物件滲透、構圖被改都會讓它掉。 校準：InStyle 摧毀構圖 = 0.060；s08 有滲透 = 0.682，乾淨 = 0.773。只能同一格內互相比較，不同格的絕對值差很大。
  • 風格分數：輸出與參考圖在 (L, 暖, S) 空間的貼合度。後面會看到這個指標被 gaming 的案例——分數 0.98 但圖是壞的。

第十組 S4：cfg > 1 讓 negative prompt 生效

發現一個一直被忽略的事：cfg=1.0 代表 negative prompt 從頭到尾都是無效的。把 cfg 拉高才能用它抑制霧感。

第十組結論

  1. cfg>1 確實讓 negative prompt 生效，內容分數也小幅提升。
  2. 但 Lightning LoRA 配 cfg>1 會產生畫面邊緣的亮框瑕疵，而且耗時加倍。
  3. 另外發現 prompt 裡的 bright high-key / luminous and airy 本身就是在要求 bloom——霧感有一部分是自己叫出來的。

第十一組 S5–S6：把「圖的貢獻」與「文字的貢獻」分離 ★ 核心診斷

第十一組結論 —— 本輪最重要的發現

  1. ★★★ 拿掉顏色文字後，沒有任何一種接線能收斂。s01 一律停在冷色（−24～−60）、s59 一律停在暗色（L30～73）。
  2. 真正在驅動風格的是文字，不是圖。style 圖只以 384×384 的視覺 token 進入 VLM，色彩訊息太弱， 在內容豐富的圖上完全推不動。唯一例外是 s08（幾乎全白的示意圖）——它太空，怎麼畫都行。
  3. 這是模型層級的能力限制，不是接線問題。後面幾組都是在嘗試繞過這個限制。

第十五組 Q：依 QwenStyle 論文修正（使用者提供）

使用者提供了 QwenStyle 技術報告—— 就是我們下載的那個模型的原始論文。從中找到兩個我做錯的細節：

論文明文規定

  1. 訓練時永遠用同一句（推論也建議照用）：
    Style Transfer the style of Figure 2 to Figure 1, and keep the content and characteristics of Figure 1.
  2. 預設 prompt 失敗時的加強句型：Transfer Figure 1 into XXX style. / Transfer Figure 1 into XXX material.

    我們輸出是 1368×760 → style 圖應縮成 760×760 正方形。我之前用 1024×1024 或直接等比例 1MP，兩種都不對。

  2. 論文的加強句型能改善收斂（暖幅 39），但那本質上還是文字驅動，且會踩到物件幻覺的地雷。
  3. ★ 新教訓：色票文字要用「純色彩形容詞」，不要用「材質/物質名詞」。warm sand → literal 沙漠。
  4. 連論文作者自己的模型、照論文自己的設定，也做不到「純靠 style 圖驅動內容豐富圖的風格轉換」。這強烈支持第十一組的診斷。

本輪總結：四十餘次實驗後的完整圖像

核心結論

  1. ★★★ 「content 圖 + style 圖 → 圖驅動的風格轉換」在目前這兩個模型上做不到。 這不是接線問題——refmethod 四種、空間 latent 三種架構、插槽五種排列、拼接、雙 LoRA 疊加、解析度加倍、 論文官方設定，全部試過。只要 prompt 裡沒有顏色文字，一律收不動。
  2. ✅ 但「色盤統一」可以完全由 style 圖驅動——用程式讀它的 LAB 統計做 grade 轉移。 暖幅 13、內容 0.99、0 秒，而且換任何一張 style 圖都自動適應。
  3. ⚠️ 「筆觸/畫風統一」只能靠 LoRA 擴散，但它套的是 LoRA 自己烘焙的風格，與你給的 style 圖無關。
  4. ❌ 兩者串接沒有免費午餐：擴散後調色會爆量化雜訊，調色後擴散會被推回去。
