# 用「修辭功能 × 呈現手法」雙軸取代單一焦點類型

舊專案（劇情動畫）用單一的「焦點類型」清單（物件／人物／動作／環境／關係／對比／細節）
描述一格要畫什麼，因為劇情片的畫面幾乎被原文決定——「他推開門，看見滿地屍體」沒什麼選擇餘地。
科普片不是這樣：「熵總是增加的」可以畫成倒塌的積木塔（類比）、分子排列示意圖（圖解）、
咖啡裡擴散的奶精（實例），或主持角色看著亂掉的房間（演繹），四種都對。

**決定**：拆成兩軸——**修辭功能**（這段在論述裡幹嘛，由原文決定，讀出來的，唯一正解）與
**呈現手法**（要用什麼方式畫，是選擇，多解並存）。

**理由**：壓成單一標籤會把「判讀」和「選擇」混為一談，人工檢視時看不出選擇的理由，
也就無從判斷對錯——而「能人工檢視鏡頭配得對不對」正是本專案的核心訴求。
兩軸之間的**對照關係**才是真正可審查的東西。

**後果**：
- 兩軸的上下文需求不同（修辭功能是逐格局部；呈現手法需要整份分鏡稿才能管節奏），
  因此必須是兩支獨立 skill，且中間形成一道障壁。
- 舊專案 48K 的「焦點類型 × 取景組合」對照表不能直接複用，需依科普情境改寫。
