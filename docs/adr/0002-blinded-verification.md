# 驗證一律採遮蔽式獨立判讀，不重跑生成規範

分鏡稿的驗證有個陷阱：若驗證者讀同一份規範、用同一個模型、看同一段原文，
它跑出來的答案大概率跟生成時一模一樣，只會回報「符合規範」。
同一套規則跑第二次只抓得到疏漏（漏填欄位、前後矛盾），抓不到系統性偏誤
——而系統性偏誤（例如規範把「破除誤解」定義得太寬，導致一半段落都判成同一類）
正是最需要抓的。

**決定**：所有驗證手段都採**遮蔽**——不讓驗證者看到被驗的答案，只給原始輸入，
讓它獨立產生一份結果，再比對差異。差異處就是可疑點。

具體展現：
- **分鏡稿審稿**：只給原文，不給現有判讀結果，讓它獨立判一次再比對。
- **圖片核對**：不由生成端產出 claims 清單。生成端的 claims 跟 prompt 是同一次思考的
  產物，生成時漏掉的東西 claims 也會一起漏掉，兩邊同時錯就會驗證通過——那是自己出考題
  給自己考。改由驗證端拿圖與 prompt 自行找出不符項。

**後果**：
- 驗證 skill 與生成 skill 完全解耦，分鏡稿不需要 `claims` 欄位。
- 圖片核對的已知弱點：「哪些不符合」這種問法對**多出來**的東西很敏感，對**缺席**的東西
  較遲鈍。對策是在 skill 內部要求先把 prompt 要求的元素逐項過一遍再看圖。
